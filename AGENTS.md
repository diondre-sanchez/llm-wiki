# LLM-Wiki schema

You maintain a personal knowledge wiki: a folder of interlinked markdown pages compiled from source
documents. The human picks the sources and asks the questions; you do the summarizing,
cross-referencing, filing and bookkeeping. Knowledge should compound: each new source improves
the existing pages instead of sitting in a pile.

## Layout (`vault/`)

- `raw/`: original sources. Immutable. Read them, never edit them.
- `wiki/sources/`: one summary page per ingested source.
- `wiki/entities/`: people, organizations, products, places, works.
- `wiki/concepts/`: ideas, methods, terms, recurring themes.
- `wiki/analyses/`: answers to questions that were worth keeping.
- `wiki/index.md`: catalog of every page with a one-line summary. Generated by the tool.
- `wiki/log.md`: append-only record of operations.

## Page conventions

- One subject per page. The filename is the page title; link with `[[Exact Title]]` (Obsidian style).
- YAML frontmatter: `title`, `type` (source | entity | concept | analysis), `summary`, `sources`,
  `tags`, `created`, `updated`. The tool writes it; page bodies never include frontmatter.
- The body starts with a 1-3 sentence overview, then `## ` sections. Typical sections:
  entity: Overview, Key facts, Relationships, Timeline, Sources;
  concept: Definition, How it works, Examples, Related, Sources;
  source: What it is, Key claims, Data and quotes, Pages touched.
- Every non-obvious fact should trace back to a source page link.
- When sources disagree, keep both claims and flag them with a `> [!warning] Contradiction` callout.
  Never silently overwrite.
- Write plainly and densely. No filler, no speculation presented as fact. Mark uncertainty explicitly.

## Operations

- Ingest: read a source, write its summary page, then create or update every entity and concept
  page it materially touches. Prefer updating an existing page to creating a near-duplicate.
- Query: answer from the wiki pages, citing them as `[[Title]]`. If the wiki lacks the answer, say so
  and name the sources that would fill the gap. Good answers can be saved as analysis pages.
- Lint: find broken links, orphan pages, duplicates, contradictions, stale claims and missing pages.

## When an agent edits the vault directly (Claude Code, Codex, ...)

Follow the same conventions. After editing pages, run `uv run wiki reindex` so `index.md` and the
search embeddings stay current. Append a log entry for each operation:
`## [YYYY-MM-DD HH:MM] <op> | <subject>`.
